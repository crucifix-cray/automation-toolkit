dispose.lol Mail Automation Reference

Observed live on 2026-08-13 at https://dispose.lol/.

This document covers the temporary Gmail/disposable-mail flow in depth: DOM selectors, UI state, observed network calls, request encoding, response decoding, polling, message details, old inboxes, and automation caveats.
Executive Summary

    The site is a SvelteKit application using SvelteKit remote functions, not a documented REST API.
    The current remote-function prefix is /_app/remote/1i1fsx0/. The 1i1fsx0 build identifier can change after deployment; do not hard-code it permanently without a fallback.
    No login is required for the anonymous current mailbox flow.
    Mailbox state persisted across reloads through an HttpOnly, Secure cookie named dispose_mailbox. It was not present in localStorage, sessionStorage, or document.cookie.
    Address creation is protected by Cloudflare Turnstile. The live form rendered the widget with response-field: false and passed a short-lived callback token to the server.
    Remote responses use HTTP 200 for both successful results and many application errors. Always inspect the JSON envelope's type field.
    The UI polls the current inbox about every 12 seconds while the page is focused and visible.

Important Limits

Use normal browser automation to obtain the mailbox cookie and Turnstile token. Do not forge, replay, or bypass CAPTCHA tokens. A direct HTTP client is only reliable when it preserves the same browser session state and uses a fresh, valid token for creation.

The site has no public API documentation exposed in the mail page. The contract below is reconstructed from the live browser's requests and shipped JavaScript bundles, so the remote prefix and exact response details should be rediscovered after major site updates.

UI State and Timing

    Initial load calls getOrCreateMailbox and getMailDomains concurrently.
    The current address is shown after getOrCreateMailbox succeeds.
    The inbox then calls getMailboxMessages using the current mailbox cookie.
    Refresh runs manually from the Refresh button or automatically about every 12 seconds when the tab is focused and visible.
    Change opens the form; creating an address updates the mailbox cookie/server state and reloads the inbox.
    Clear calls clearMailboxMessages, increments a local clear version, and empties the displayed list.
    Clicking a message calls getMailboxMessage, then flips the inbox panel to the detail view.
    Closing the detail view is local state only; it does not make another API call.

Transport Encoding

The payload is SvelteKit/devalue-style table serialization followed by UTF-8 and unpadded base64url encoding.

Conceptually:

transport(value) = base64url_no_padding(utf8(devalue_stringify(value)))

Observed examples:
Logical value	Serialized table form	Encoded payload
No arguments	Empty payload	""
{ assignmentId: undefined }	[{"assignmentId":-1}]	W3siYXNzaWdubWVudElkIjotMX1d
{ id: "<id>", refresh: true }	[{"id":1,"refresh":2},"<id>",true]	Depends on <id>.
{ type: "custom_domain", username: "<u>", domain: "<d>", turnstileToken: "<t>" }	Object keys point to later table entries	Depends on values.

Important encoding rules:

    undefined is the -1 sentinel. Do not replace it with null when matching the current-mailbox request.
    Strings, booleans, numbers, objects, arrays, and dates are stored in a shared table and referenced by numeric indexes.
    Dates are encoded as [ + "Date" + ISO-8601 string + ] and decoded back to Date objects.
    The base64 is URL-safe (+ becomes -, / becomes _) and has no = padding.
    Keep object key order stable if comparing payloads byte-for-byte.
    The site currently uses ordinary mail arguments and Date-based cursors; no separate mail-specific transport handler was observed.

In JavaScript, a pinned devalue package compatible with the site's SvelteKit version can provide the table stringify/parse behavior. If implementing the table format yourself, test against the exact payload above before using it in a client.
Browser-Assisted JavaScript Client Skeleton

This is a protocol skeleton, not a CAPTCHA bypass. It assumes it runs in the same browser origin/session as the page, so cookies are included automatically.
js

import { stringify, parse } from "devalue";

const remotePrefix = "/_app/remote/1i1fsx0";

function toBase64Url(text) {
  const bytes = new TextEncoder().encode(text);
  let binary = "";
  for (const byte of bytes) binary += String.fromCharCode(byte);
  return btoa(binary)
    .replaceAll("=", "")
    .replaceAll("+", "-")
    .replaceAll("/", "_");
}

function transport(value) {
  return toBase64Url(stringify(value));
}

async function decodeEnvelope(response) {
  const envelope = await response.json();
  if (envelope.type === "error") {
    throw new Error(envelope.error?.message || "Dispose remote call failed");
  }
  if (envelope.type !== "result") {
    throw new Error(`Unexpected response type: ${envelope.type}`);
  }
  return parse(envelope.result);
}

async function remotePost(name, args) {
  const response = await fetch(`${remotePrefix}/${name}`, {
    method: "POST",
    credentials: "include",
    headers: {
      "Content-Type": "application/json",
      "x-sveltekit-pathname": location.pathname,
      "x-sveltekit-search": location.search
    },
    body: JSON.stringify({
      payload: args === undefined ? "" : transport(args),
      refreshes: []
    })
  });
  return decodeEnvelope(response);
}

async function remoteGet(name, args) {
  const query = args === undefined ? "" : `?payload=${encodeURIComponent(transport(args))}`;
  const response = await fetch(`${remotePrefix}/${name}${query}`, {
    credentials: "include",
    headers: {
      "x-sveltekit-pathname": location.pathname,
      "x-sveltekit-search": location.search
    }
  });
  return decodeEnvelope(response);
}

const domains = await remoteGet("getMailDomains");
const current = await remotePost("getOrCreateMailbox");
const messages = await remoteGet("getMailboxMessages", {
  // The explicit undefined matches the site's current-mailbox call.
  assignmentId: undefined
});

If devalue is not available, run the calls in the page and let the site's own SvelteKit transport wrapper handle encoding, or implement a tested table serializer. Plain JSON.stringify(args) is not compatible with this API.
Recommended Polling Flow
js

async function waitForSubject(subject, timeoutMs = 120000) {
  const deadline = Date.now() + timeoutMs;
  while (Date.now() < deadline) {
    const result = await remoteGet("getMailboxMessages", {
      assignmentId: undefined
    });
    const match = result.messages?.find((m) => m.subject === subject);
    if (match) return match;
    await new Promise((resolve) => setTimeout(resolve, 12000));
  }
  throw new Error(`Timed out waiting for ${subject}`);
}

async function openMessage(row) {
  const result = await remotePost("getMailboxMessage", {
    id: row.id,
    refresh: true
  });
  return result.message;
}

Practical rules:

    Avoid concurrent polling calls; the live UI can issue duplicate requests during transitions.
    Match on id when possible. Subject text is not unique.
    Use receivedAtValue for sorting, not the localized receivedAt label.
    Check error, readOnly, and showSet on every message response.
    Refresh only while the tab is visible/focused if mirroring the site's behavior.
    If a detail response includes htmlBodySrcdoc, treat it as untrusted HTML and keep it sandboxed.

Pagination
Current mailbox messages

When nextCursor is non-null, call getMailboxMessages again with:
js

{
  assignmentId: assignmentId ?? undefined,
  cursor: {
    ...nextCursor,
    receivedAt: new Date(nextCursor.receivedAt)
  }
}

The UI specifically rehydrates receivedAt as a Date before serializing the next request. The server cursor may contain additional fields; preserve them unchanged.
Historical mailbox search

For getMailboxHistory, preserve the cursor and rehydrate its timestamp:
js

{
  ...(search ? { search } : {}),
  cursor: {
    ...historyCursor,
    allocatedAt: new Date(historyCursor.allocatedAt)
  }
}

Do not send an ISO string without converting it to a Date if using the same transport format.
Turnstile and Session Details

The page loaded:

https://challenges.cloudflare.com/turnstile/v0/api.js?render=explicit

The current site bundle configured:

sitekey: 0x4AAAAAADIVYc8ZvYOIz-Bc
appearance: interaction-only
response-field: false
retry: never

The callback token is passed to createMailbox as turnstileToken. It is not exposed as a normal form input. A direct client should either:

    drive the real form in a browser and let the widget supply the token, or
    use an approved/authorized integration that can supply a valid token.

Do not copy a token from an earlier request. It is short-lived and tied to the browser/security challenge.

The relevant cookie observed through the browser cookie store was:

dispose_mailbox; domain=dispose.lol; path=/; Secure; HttpOnly; SameSite=Lax

Its value is a mailbox-state token and should be treated as sensitive. Page JavaScript cannot read it with document.cookie, but browser fetch sends it automatically with credentials: include.
Error Handling

Handle all of these cases:

    Network failure or timeout.
    HTTP response that is not JSON.
    JSON envelope with type: "error" even when HTTP status is 200.
    Successful envelope whose decoded object has a non-null error.
    needsCaptcha: true from mailbox creation.
    showSet: true, which indicates the active mailbox is unavailable or changed.
    readOnly: true for expired historical mailboxes.
    Empty messages with nextCursor: null, which is a normal empty inbox.
    Missing htmlBodySrcdoc and textBody, which should render as an empty/unavailable body rather than crashing.
